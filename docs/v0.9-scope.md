# Autonomous Studio v0.9 — Final Scope

## Goal

v0.9 makes the existing full-video workflow more editorially controllable and more resilient
without expanding into model administration. A full production must obtain approval for its
timing-validated script before it spends an image-generation request or acquires source media.
It may then combine rights-compatible documentary photographs with generated illustration while
retaining enough provenance for a human publication decision.

Model discovery, model listing, voice selection, and Telegram model configuration are explicitly
out of scope. Existing environment-based provider configuration remains unchanged.

## Included

### 1. Timing-validated script approval

- `/full` performs research, directing, voice synthesis, and bounded timing repair first.
- Telegram then sends candidate hooks, the chosen hook, the complete measured script, and its
  measured duration.
- No visual acquisition or image-generation request occurs before approval.
- Approval creates an immutable script lock over the research, narration, voice segments,
  measured voice artifacts, timing validation, and target duration.
- Any script revision creates a new project version, keeps the accepted research, repeats timing
  validation, and requires a new script approval.
- Asset preparation refuses to continue if the approved lock is absent or no longer matches.

### 2. Bounded provider recovery

- Incomplete OpenAI responses are retried internally once and recorded as small diagnostic
  receipts without storing partial generated text.
- Structured responses that fail semantic validation are marked rejected so `/retry` cannot
  replay the same invalid cache entry.
- Narrative generation aims below the hard duration ceiling and gets bounded internal repair.
- Shot-plan contradictions that are mechanically unambiguous are normalized before validation.
- Errors distinguish provider incompleteness, provider validation, asset planning, and narration
  timing; Telegram does not recommend an unchanged retry for deterministic validation failures.

### 3. Visual-plan integrity

- A dedicated metric, location, timeline, or chart value cannot also occupy the headline slot.
- Redundant annotations that merely repeat the headline or narration are removed.
- Every narrated full-video scene declares an image, map, chart, or explicitly justified
  text-only strategy.
- Maps remain limited to genuinely geographic narration.

### 4. Rights-aware documentary stills

- The asset planner may request either a generated illustration or an archival still.
- Real people, places, buildings, objects, and documented events prefer Wikimedia Commons media
  carrying Public Domain, CC0, or CC BY terms.
- The exact downloaded source, portrait derivative, source metadata, edit manifest, attribution,
  and licence evidence are retained.
- Generated illustrations remain the bounded fallback when no compatible archival result is
  available.
- Archival use is marked for human identity, context, privacy, personality, trademark, and
  editorial review before publication.
- Both source and derivative images appear in the project image gallery for thumbnail selection.

### 5. Durable setting evidence

- `/closed-caption yes|no` is accepted as an alias for `/closedcaption yes|no`.
- `/settings` reports the caption and generated-image-budget values that the next project will
  snapshot.
- New projects persist those values and whether they came from a Telegram preference or the
  environment default.
- Preference changes are recorded in an append-only runtime audit table.

## Excluded

- Telegram model or voice selection.
- Provider model discovery or availability probing.
- New publishing integrations.
- Automated legal clearance of people, trademarks, privacy, or contextual use.
- Automated recovery or mutation of previously failed projects.

## Acceptance criteria

1. A `/full` project reaches script approval with zero prepared visual assets and zero image API
   requests.
2. Approved script content cannot change before asset preparation without invalidating the lock.
3. Revising the script reuses research but creates a new version and a new lock.
4. An incomplete provider response is retried once and leaves a diagnostic receipt.
5. A rejected structured cache entry is not replayed by `/retry`.
6. A repeated metric cannot be rendered in two primary text slots.
7. An archival acquisition retains source and derivative files plus machine-readable rights and
   edit records.
8. Caption aliases, preference auditing, and project creation snapshots are covered by tests.
9. The existing deterministic test suite and lint checks remain green.
