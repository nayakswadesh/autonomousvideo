# Autonomous Studio v0.8 scope

v0.8 is limited to publication preferences, human publication clearance, a complete root-level
publication package, and usage/cost reporting. It does not add operational infrastructure,
automatic upload, new media providers, or a new renderer.

## 1. Optional burned-in closed captions

Telegram exposes one persistent setting for projects created in the future:

```text
/closedcaption
/closedcaption yes
/closedcaption no
```

Telegram command names cannot contain a hyphen, so `/closed-caption` is not the canonical command.
Calling `/closedcaption` without an argument reports the saved value. `yes` or `no` persists the
preference in studio runtime settings and snapshots the effective value into every newly created
project. Changing the setting never mutates an in-progress or historical project.

- `yes`: render the existing timed, burned-in narration captions.
- `no`: omit timed narration captions from the video pixels.

This setting does not remove editorial titles, labels, metrics, maps, or chart annotations. It
controls only narration captions. v0.8 does not create an SRT/VTT track or manage YouTube's
automatic captions or dubbed tracks. YouTube metadata must retain the correct original language
so those external features have the right source language.

Existing projects that do not contain the new setting retain today's captioned behavior for
backward compatibility. Layout QA must test both modes and confirm that `no` leaves no narration
caption cards in rendered frames.

## 2. Publication metadata and clearance gate

The workflow gains a distinct `PUBLICATION_CLEARANCE` state and `publication` approval gate:

```text
PROTOTYPE_APPROVAL
→ creative preview approved
→ PUBLICATION_CLEARANCE
→ publication package reviewed
→ COMPLETED
```

Creative preview approval no longer means publication clearance. The publication review presented
through Telegram contains the selected title, complete description, recommended thumbnail, rights
summary, factual/pronunciation reminder, disclosure status, and usage/cost summary. It supports
Approve, Revise, and Reject with the same version- and artifact-bound protections as the preview.

Approval records that the human reviewed:

- factual accuracy and uncertainty language;
- narration and pronunciation;
- title, description, hashtags, and thumbnail;
- music licensing and any required attribution;
- generated-image and synthetic-media disclosures; and
- unresolved rights warnings.

`release-status.json` is generated as both an immutable versioned artifact and a latest root-level
export. It records project/version, status (`pending`, `cleared`, or `rejected`), actor, timestamp,
feedback, approved artifact IDs and SHA-256 values, checklist results, and unresolved blockers.
Only a cleared publication decision advances the project to `COMPLETED`.

Metadata-only revision feedback must not repeat research, speech, image generation, music
selection, or video rendering. Feedback that changes factual narration or visuals starts a normal
creative revision instead.

### YouTube title and description

`youtube-title.txt` is added to the immutable publication artifacts and project root. The selected
title must be accurate, concise, front-load the important subject, and make the same promise as the
thumbnail, opening frame, and spoken hook.

The description generator is revised to produce:

1. a concise opening that extends the video's curiosity without repeating the title mechanically;
2. a novice-friendly summary of what the viewer will learn;
3. a natural engagement prompt when appropriate;
4. factual sources;
5. required music attribution and licence links;
6. synthetic-media disclosure; and
7. no more than three directly relevant hashtags, normally `#Shorts` plus up to two topic-specific
   tags.

Hashtags must be supported by the actual topic and cannot be generic trend bait. The studio makes
no promise that hashtags will maximize reach; title/thumbnail promise, viewer satisfaction, and
topic relevance take priority.

## 3. Complete root publication package

Before publication clearance, immutable candidate artifacts are prepared for review. After the
publication gate is approved, the project root contains the latest cleared package:

```text
final-video.mp4
youtube-title.txt
youtube-description.txt
youtube-metadata.json
selected-thumbnail.png
release-status.json
usage-report.json
```

The root files are replaceable convenience exports. Versioned artifacts remain authoritative and
must continue to verify by checksum. `final-video.mp4` must be byte-identical to the approved
prototype artifact, and `selected-thumbnail.png` must be copied from a persisted thumbnail
candidate. Pending or rejected publication packages must not replace a previously cleared root
package.

Existing v0.7 projects remain loadable. A completed historical project is not forced through the
new gate; its existing human approval remains historical truth.

## 4. Usage and cost reporting

Every creative version produces an immutable `usage-report.json`; the latest cleared report is
also exported at the project root. It aggregates by stage, provider, model, and asset type:

- request count and provider request IDs when available;
- input, cached-input, output, audio, and image tokens when returned;
- web-search calls;
- TTS requests and generated audio duration;
- image reservations, successful generations, cache hits, and ambiguous requests;
- local rendering/mixing duration; and
- known, estimated, and unknown monetary cost.

Cost fields are explicit:

- `provider_reported_cost`: only a charge returned by or reconciled from the provider;
- `estimated_cost`: usage multiplied by a versioned rate-card snapshot;
- `currency`, `rate_card_source`, `rate_card_effective_at`, and `calculation`; and
- `unknown_cost_items`: anything that cannot be priced honestly.

An estimate is never labelled as billed cost. The OpenAI organization usage/cost endpoints may be
used only when separately configured with suitable administrative access; v0.8 must not require an
admin key. Without that access, response-level usage plus a documented rate-card snapshot produces
an estimate and unknown values remain unknown. No secret or authorization header may enter the
report.

The publication-clearance Telegram message includes a compact summary; detailed usage remains in
the JSON artifact.

## Acceptance checks

- Caption preference persists across worker restart and applies only to future projects.
- Caption-on and caption-off renders pass layout, audio/video, and deterministic fixture tests.
- Caption-off frames contain no narration caption cards while retaining editorial overlays.
- Preview approval advances to publication clearance rather than directly to completion.
- Publication decisions are bound to exact project version and artifact checksums.
- Metadata-only revision performs no research, TTS, image, music, or video provider calls.
- Root publication files appear only for a cleared package and match their immutable artifacts.
- Titles remain within YouTube's limit and descriptions within its limit.
- Descriptions contain at most three relevant hashtags and all required credits/disclosures.
- Usage totals reconcile with persisted provider responses, reservations, caches, and artifacts.
- Unknown costs stay explicitly unknown; estimated and provider-reported costs are distinguishable.
- Older project snapshots remain loadable and retain their original approval history.

## Explicit non-goals

v0.8 does not include:

- automatic YouTube upload or publishing;
- Telegram worker supervision, Windows startup, backup/restore, or log rotation;
- credential rotation or secret-store migration;
- Remotion, generative-video providers, or a new motion-design system;
- SRT/VTT generation, word-level captions, or YouTube caption/dub management; or
- additional research, narration, image, music, or rendering features beyond what this scope
  requires.
