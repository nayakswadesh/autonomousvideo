# v0.5 validation — 2026-09-14

## Outcome

v0.5 adds an explicit full-production mode to the existing resumable studio. Prototype mode
remains 10–15 seconds with at most six shots. Full mode requires 45–60 seconds and 6–18 shots.
Old project snapshots omit `production_mode` and therefore continue to validate as prototypes.

Ranked briefs may set `expected_rank_count`. Before narration or asset expenditure, the studio
then verifies that research contains the complete contiguous ranking, the story presents every
rank exactly once in reverse order, each rank shot references its subject claim, and a source
card is present. A versioned `scope-validation.json` is required by the final full-preview gate.
Timing repairs and presentation-only revisions regenerate this validation for their new version.
If the optional expected count was omitted but research is ranked, all researched ranks are still
mandatory; a prose command such as `/full top 5 ...` therefore cannot degrade to a partial story.

The OpenAI-backed director uses the same Structured Outputs contract with a mode-specific prompt.
Full mode requests 6–18 shots and complete ranked coverage; the existing one-repair limit remains.
Research requests now carry production mode and expected rank count as explicit structured context.
The implementation continues to set `store=false`, caps tool/output use, and records provider
responses and usage. This follows the official OpenAI Responses API and Image API contracts:

- https://developers.openai.com/api/reference/resources/responses/methods/create
- https://developers.openai.com/api/reference/resources/images/methods/generate
- https://developers.openai.com/api/docs/models/gpt-image-2

## Full-production behavior

- Narration is synthesized and checkpointed per segment. Measured reflow is frame-aligned and
  bounded by 60 seconds in full mode; prototype mode remains bounded by 15 seconds.
- If reflow cannot fit, at most two internal script rewrites are allowed. Full-mode word budgets
  are 95 and 75 words; the research and complete countdown still have to pass scope validation.
- If measured narration still cannot fit after both internal versions, preview-policy projects
  enter `NARRATION_APPROVAL` instead of failing. Telegram sends the concise complete script with
  Revise and Reject actions. A human revision reuses research, creates a new version, resets the
  bounded timing cycle and resumes at directing; approval without trimming is not accepted.
- Audio mixing, narration ducking, intentional silence, normalization, clipping checks and
  container validation use the existing provider-independent services.
- The base and editorial source cards support up to five citations. Editorial layout still fails
  closed on unreadable text rather than truncating it.
- Asset plans support up to 18 display looks and 18 generated images. A project's persisted
  `max_image_requests` remains authoritative; the default remains two. CLI full-project creation
  can accept an explicit 1–18 budget, but it does not dispatch API calls itself.
- Telegram `/full [rank-count] <topic>` creates a 55-second project. The worker uses the configured
  image cap and sends the scope report, narration report, asset report, QA and MP4 followed by
  exactly one final approval request.
- QA records production mode, shot count, expected rank count and rendered rank order.

It exercises the same full-duration validation and one-review orchestration without any
earthquake-specific code.

PNGs; this test consumes no OpenAI usage.
